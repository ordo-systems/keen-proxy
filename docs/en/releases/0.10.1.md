# 0.10.1 — update recovery

**Released on 2026-11-25.** [Version history](index.md) · [GitHub release and downloads](https://github.com/ordo-systems/keen-proxy/releases/tag/v0.10.1)

## If the in-panel update fails { #entware-update-recovery }

Sorry — we broke in-panel updates on some routers. An older installed version runs its own embedded installer, so it can abort before the v0.10.1 fix takes effect.

**What broke:** We made temporary rules that block forwarded traffic during a restart mandatory. On some Entware routers, the firmware rejects the IPv6 `FORWARD` rule, so the old installer stops before replacing the binary.

**What we fixed:** The new installer attempts the IPv4 and IPv6 rules independently and keeps any rule it manages to install. It still checks that traffic interception is active after restart and rolls back if the new service does not start with interception. See [PR #58](https://github.com/ordo-systems/keen-proxy/pull/58).

On Keenetic or Netcraze with Entware, disable automatic installation if enabled. Connect to the router over SSH **from your local network** and run:

```sh
curl -fsSL https://raw.githubusercontent.com/ordo-systems/keen-proxy/main/tools/bootstrap.sh | /opt/bin/sh -s -- --version v0.10.1
```

Append `--lite` if you use the lite build. This keeps your configuration and restarts the service when replacing the installed version. If a forwarding guard cannot be installed, the script warns and continues; traffic for that IP family may bypass KeenProxy during the restart. If you cannot allow that, append `--require-guard` to abort the update when a required guard cannot be installed.

For native OpenWrt, use the [separate OpenWrt command](../getting-started.md#native-openwrt-installation), not the Entware command above. See the [update guide](../getting-started.md#update-from-the-panel) for recovery and rollback.
